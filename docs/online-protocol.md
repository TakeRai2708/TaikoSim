# TakeTaiko オンラインの約束ごと（設計メモ）

2026-11-26 作成。まだ**設計だけ**で、通信の部分は作っていない。
曲の配布の中身（`TakeTaikoSimulator/Online/SongShare.cs`）だけは先に作ってあって、テスト（`tools/songshare-check`）も通っている。

## 0. 決まっていること（たけらいと相談済み）

| 項目 | 決めたこと |
|---|---|
| 仕組み | Epic Online Services（EOS）。ロビー（ルーム）と P2P を使う |
| ログイン | アカウントなし。EOS Connect の Device ID（PCごとの匿名ID）で自動ログイン |
| 遊べるもの | TaikøNauts と同じ全部：通常演奏・段位道場・ローテプレイ・観戦・チャット・選曲担当 |
| 曲 | ホストの曲を使う。持っていない人・中身が違う人には、ホストから配る。もらった曲は残す |
| もらった曲の置き場所 | ホストの曲のジャンル（box.def の #GENRE → #TITLE）と同じジャンルのフォルダ。無ければ `Songs/未分類` |
| 演奏中の表示 | 通常演奏は 2P・3P・4P…とほかの人のレーンも並べる（見た目は TaikøNauts の録画を見てから決める） |

## 1. 使う EOS の機能

| 機能 | 何に使う |
|---|---|
| Connect（Device ID） | ログイン。プレイヤーの ID（ProductUserId）をもらう |
| Lobby | ルーム。作る・探す・ID で入る・抜ける・ホストの交代・ルームの設定（属性） |
| P2P | ルームの中のやりとり全部（チャット・選曲・曲の配布・演奏中のスコアなど） |

- ルーム一覧に出さないルームは、Lobby の「公開しない」設定（招待/ID 参加のみ）にする
- LAN（TaikøNauts の「LAN」タブ）は、EOS を使わずに UDP で同じメッセージを送る形にする予定（あとで）

## 2. ルームの属性（Lobby の属性に入れる。一覧で見えるもの）

| 名前 | 中身 |
|---|---|
| `ver` | 通信の版（下の「5. 版の決まり」）。違うと入れない |
| `kind` | `normal`（通常演奏）／ `dan`（段位道場）。あとから変えられない |
| `name` | ルーム名 |
| `max` | 最大人数（TaikøNauts は 2〜8） |
| `spectate` | 観戦を許すか・観戦の最大人数 |
| `movie` | 背景映像を配布するか |
| `danEffect` | 段位の曲間演出を配布するか（`dan` だけ） |
| `state` | `lobby`（待っている）／ `playing`（演奏中） |

ルームの中の細かい設定（遊び方・選曲担当など）は P2P で送る（属性は一覧に出す最小限だけ）。

## 3. P2P の使い方

- ソケット名：`TakeTaiko`
- チャンネル：
  - **0：ふつうのやりとり**（届く・順番どおり）。ルーム・選曲・準備・リザルト・チャット
  - **1：曲の配布**（届く・順番どおり）。大きいデータはこっちだけで流して、ほかのやりとりを詰まらせない
  - **2：演奏中のようす**（届かなくてもいい・新しいものだけ使う）。スコア・ゲージ・コンボ
- 1つの包みは EOS の上限（1170 バイト）以内。曲の小分けは `SongShare.ChunkSize` = 1100 バイト
- 包みの形：`[種類 1バイト][中身]`。中身は小さい JSON（チャンネル0）か、決まった形のバイト列（チャンネル1・2）
- **ホストが正しい**：ルームの状態（だれがいるか・選曲担当・選んだ曲・始まる時刻）はホストが決めて全員に配る。ほかの人はホストにお願いを送るだけ

## 4. メッセージの種類

### 4-1. ルーム（チャンネル0）

| 種類 | だれ→だれ | 中身 |
|---|---|---|
| `Hello` | 入った人→ホスト | 通信の版・ゲームの版・名前・ネームプレート（称号・段位・プレートの番号）・観戦かどうか |
| `Welcome` | ホスト→入った人 | 受け入れた（ルームの今の状態を全部）／断った（理由：版が違う・満員・観戦できない） |
| `RoomState` | ホスト→全員 | プレイヤー一覧（並び・名前・プレート・準備OKか・観戦か）・遊び方・選曲担当・選んだ曲 |
| `Leave` | だれでも | 抜ける。ホストが抜けたら、Lobby の決まりで次のホストに交代（交代したら `RoomState` を送り直す） |
| `Settings` | 選曲担当→ホスト | 遊び方の変更（ふつう／ローテプレイ・区切り・間隔・担当順・直前まで隠す）・ランダム交代・配布設定 |
| `Chat` | だれでも→ホスト→全員 | 文字（200文字まで）。ホストが送り主をつけて配り直す |
| `ToSpectate` / `ToPlayer` | 本人→ホスト | 観戦に切り替え／プレイヤーに戻る |
| `Disband` | ホスト→全員 | ルームを解散。全員ロビーへ戻って「ルームが解散されました」 |

### 4-2. 選曲と曲の配布（チャンネル0・1）

1. 選曲担当が曲を決める → ホストへ `SongPick`（ホスト以外が選曲担当なら、その人が自分の曲を「ホストの曲として」使う形はとらない。**曲はいつもホストのもの**なので、選曲担当は「ホストの曲一覧」から選ぶ）
   - 選曲担当がホスト以外のときは、ホストから曲の一覧（指紋・タイトル・ジャンル・難易度）を先に受け取る（`SongList`、小分けして送る）
2. ホストが `SongShare.Create` で**マニフェスト**を作って全員へ `SongOffer`（マニフェストの JSON。1100 バイトをこえたら小分け）
3. それぞれが `SongLibrary.FindLocal` で同じ指紋の曲を探す
   - 持っている → `SongHave`
   - 持っていない → `SongWant`
4. ホストは `SongWant` の人に、チャンネル1で `SongChunk`（`[種類][番号 4バイト][データ]`）を順番に送る（`SongPackageReader.ReadChunk`）
   - 何人もほしい人がいるときは、同じ番号を全員に送る
   - 送る速さは、EOS の送信待ちの量を見て調整する（詰めすぎない）
5. もらう人は `SongReceiver.Accept` でためる。`SongProgress`（○%）を 0.5 秒ごとにホストへ → ホストが `RoomState` で全員に見せる（「ダウンロード中 ○%」）
6. 全部そろったら `SongReceiver.Finish`。中身の指紋を確かめて、ジャンルのフォルダに置く
   - 確かめて合わなかったら、もう一回最初から（2回失敗したら、その人は今回は不参加）
   - 足りない番号があれば `SongResend`（`SongReceiver.Missing`）
7. 置き終わったら `SongReady`。曲一覧を読み直して（その曲だけ足す）、難易度選びへ

決まり：
- **ホストが曲を「決めた」ときに配り始める**（カーソルを合わせただけでは配らない）
- 受け取るファイルは `SongShare.Validate` の決まりを通ったものだけ（場所は .tja のフォルダの中だけ、種類は譜面・音・画像・動画だけ、1曲 300MB まで）
- 指紋は .tja と音源の中身から作る（画像・動画は入れない。動画を配らない設定でも同じ曲として扱うため）

### 4-3. 演奏（チャンネル0・2）

1. それぞれ難易度・演奏オプションを選ぶ → `Ready`（難易度・オプション）
2. 全員そろったらホストが `StartAt`：**ホストの時計で ○ ミリ秒に、曲の 0 秒**
   - 時計合わせ：ルームにいる間、ホストと `Ping` / `Pong`（送った時刻・受けた時刻）を 2 秒ごとに。往復の時間の半分を遅れとして、ホストの時計とのずれを出す（直近 8 回のうち、往復がいちばん短い回を使う）
   - 読み込みに時間がかかる人のために、`StartAt` は今から 3 秒後以上にする
3. 演奏中、0.1 秒ごとにチャンネル2で `Live`：スコア・コンボ・ゲージ・良/可/不可/連打の数・今の分岐
   - ほかの人のレーンに音符の結果も出すので、叩いた結果を `Hits`（音符の番号・結果）でまとめて送る（0.1 秒ぶん）
   - 判定と音は**自分の PC だけで決める**（通信の遅れで判定が変わらないように）
4. 終わったら `Result`（最終のスコア・数・クリア状態）。全員の `Result` がそろうか、10 秒たったらリザルト画面
5. 途中で抜けた人は「切断」と表示して、その人のレーンは止める

### 4-4. ローテプレイ（交代で叩く）

- ホストが「交代の区切り（小節ごとなど）・間隔・担当順」から、**だれがどの小節を叩くか**を決めて `StartAt` といっしょに送る
- 自分の番以外の小節は叩いても判定しない。スコアは全員で1つ（ホストが `Live` を集めて合計を配る）
- 「次の人を交代の直前まで隠す」が ON なら、次の人の名前は交代の 1 小節前に出す

### 4-5. 段位道場ルーム

- `kind = dan`。曲はホストの段位（dan.def / dan.json と3曲）を配る（3曲ぶん、4-2 を3回）
- 「全員で演奏」か「交代で演奏」かを選べる（TaikøNauts の説明より）
- 段位の曲間演出（ふすま・aup2）を配るかどうかは `danEffect`

### 4-6. 観戦

- 観戦の人は `Live` / `Hits` を受け取るだけ（叩かない）
- 曲は観戦の人にも配る（画面に出すため）

## 5. 版の決まり

- 通信の版 `ver`（整数）。メッセージの形を変えたら 1 上げる。**版が違う人とは遊べない**（`Welcome` で断る・ルーム一覧で「版が違います」）
- 曲のマニフェストの形は `SongManifest.Format`（今は 1）

## 6. 安全のための決まり

- 届いたものは全部「信用しない」：大きさ・番号・文字数の上限を見て、合わないものは捨てる
- 曲のファイルは `SongShare.Validate` を通ったものだけ書く。書く場所は Songs の中だけ
- チャットは 200 文字まで、1 秒に 3 回まで
- ルーム一覧に出さないルームでも、ID を知っている人は入れる。ID はチャットに出さない

## 7. まだ決めていないこと

- ほかの人のレーンの並べ方・大きさ（録画待ち）
- 選曲担当がホスト以外のとき、ホストの曲一覧をどう見せるか（全部送ると重いので、ジャンルごとに少しずつ？）
- LAN のつなぎ方（UDP の細かい形）
- NAT を越えられないとき（EOS のリレーが使われるはずだけど、遅くなる。曲の配布にかかる時間）
