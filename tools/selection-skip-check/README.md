# 選曲の同じ側2打・逆側無視の判定

.NET 10 SDKで、外部パッケージ・Raylib・BASSなしに実行できます。

```sh
dotnet run --project tools/selection-skip-check/Check.csproj
```

実際のSongSelectSkipGesture.csをコンパイルして29項目を確認します。

- 最初の入力で、その方向へ通常1項目移動。
- 250ms以内は逆側の入力を無視。最初の側・時刻を変えない。
- 同じ側の2打目で、その方向へスキップ。
- 左→右→右なら、左へ1項目動くだけ。右2打ではスキップしない。
- 左→右→左なら、右を無視して左2打として左へスキップ。
- 250msを過ぎたら、左右どちらでも新しい1打目として受付。

このチェックは入力の時間と方向のみ。「とじる」を除く7項目の移動、0.5秒ロック、実キー入力・クリック・音声・描画はWindowsで別途確認してください。
通常移動では「とじる」を選べます。スキップは見出しも数えず、ジャンル・ランダム項目は従来どおり含みます。
SDK不在のため、このチェック・本体ビルド・Windows実機確認は未実施です。

## 「とじる」からのスキップ（実機確認項目）

1打目の通常移動前に「とじる」にカーソルがあれば、同じ側の2打目でその方向の次の「とじる」へ移動します。
1打目で既に隣の曲へ動くため、出発位置を保持して次の「とじる」を探します。
曲から始めた場合は、従来どおり「とじる」を数えず7項目移動します。
確認するケース：前後両方向、一覧の端からの周回、「とじる」が1つの短い一覧、逆側の打鍵を挟む場合、通常1打で隣の曲へ移動できること。
既存の純粋な入力判定チェックは、この画面内の移動処理を実行しません。
