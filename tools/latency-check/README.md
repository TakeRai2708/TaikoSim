# latency-check（音の遅れを録画から測る）

11/26 に作った。人が叩いて測る（タイミング調整）と ±30ms くらいばらつくので、録画から機械的に測る。

1. `python make_song.py` で `測定用/` を作り、TakeTaiko の `Songs` に入れる（120BPM・0.5秒ごとにピッ）
2. 設定で SE（効果音）を 0、演奏オプションでオートを ON
3. OBS（60fps・デスクトップ音声あり）で録画しながら「遅れ測定」のおにを 40秒くらい流す
4. `python measure.py 録画.mkv`（numpy・scipy・ffmpeg が要る）
   - 画面：レーンの赤い音符の位置から、判定の円（x=620）に来る時刻を出す（1つの音符を何コマも使うので、1コマより細かく出る）
   - 音：2kHz のピッの鳴り始め
   - 「ピッ − 音符」の差（ms）。プラス = 音が遅い

注意：OBS が録るのは Windows の音声エンジンに入る前の音。スピーカー・イヤホンまでの遅れ（共有のエンジン約 20ms・機器の中）は入らない。

11/26 の結果（たけらいの PC）：BASS 30ms = +4.1ms（±1.0）、WASAPI 共有（エンジン 20ms を引く）= −21.8ms（±4.9）
→ BASS / DirectSound にも、WASAPI 共有と同じエンジンの遅れ（既定の機器の周期 × 2）を足した（AudioManager.BassOutputLatencyMs）

## 叩いた音（ドン・カッ）の遅れ（11/27）
- 曲の音量（Music）を 0、効果音（SE）を 100 にして同じように録画すると、オートが叩いた音の鳴り始めを測れる（measure.py のままでよい。ドンの鳴り始めの高い音を拾う）
- たけらいの PC（1.0.21.1）：BASS 30ms = +81ms（±1.2）、WASAPI 共有（叩いた音は別の共有出力）= +40ms（±2〜5）。耳にはさらに約20ms
- 曲は遅れの分だけずらして合わせられるが、叩いた音は押した瞬間にしか鳴らせないので、出力の道の遅れがそのまま聞こえる
- 対策：BASS の機器の更新間隔（DevicePeriod）を 1ms に頼む（Windows 10 以降の低遅延の共有モードに対応していれば短くなる。効くかは未確認）。いちばん効くのは WASAPI 排他
